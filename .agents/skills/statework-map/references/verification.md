# Verify coverage and execution separately

Run the helper after exporting a complete bundle:

```text
node <skill>/scripts/audit-map.mjs --app <built-app> --bundle <private-bundle.json> --ledger <private-research.json> --out <new-private-report.json>
```

It imports into memory through StateWork's validator, checks ledger accounting and emits every task's app-computed readiness with external access disabled. It also flags missing packets, unsupported completion records and uncaptured/unreadable material. A structurally valid map can still be semantically wrong. The script does not prove the ledger includes every real-world requirement, and it does not approve procedures or run work.

Reconcile the ledger against the full original indexes, not against task count. For each mandatory/chosen deliverable, verify its task, exact specification, original inputs, prerequisites, ordered procedure, required output, acceptance and destination. If a row is intentionally deferred/excluded, verify the reason and visible recovery/selection. Report denominators separately: sources inspected/known, requirements mapped/known, packets reviewed/tasks, and executable tasks/tasks. Do not fold unknown sources into a success percentage.

Read every auditor issue. Draft packets and inaccessible branches are acceptable recorded findings, not a complete/executable result. Missing original figures, ambiguous units, missing grading rules, unknown selections, pending confirmations and stale packets need distinct causes and recovery actions.

Test whether confirming worker access could accidentally clear an unresolved source-knowledge gap. Review applies only to the scope actually inspected. Also reconcile required originals against attachment limits and stored bytes; record any derivative's inspected page/member lineage and preserve storage blockers for essential missing content.

## Fresh-worker dry run

Select representative tasks after building, without choosing only the simplest or most complete ones. Include a random sample, visually specified work where present, a prerequisite chain and a blocked/conditional path. Record the selection method. Retrieve only app handoffs, captures and original files in this pass. Assume required apps installed only when the test explicitly declares that assumption; never persist invented access confirmations.

For each sampled task, print or save the exact supplied instructions and assess: can a worker determine the intended result, reproduce all required inputs, choose the correct next action, verify the result and deliver it with the supplied information? Name the exact blocking fact/file, not merely “needs more context.” Do not create a CAD model, submit a form or perform mapped work during a dry run.

Inspect the actual app's map and current-step view at desktop and narrow widths. Open source/reference/file links. Check a prerequisite blocks the right step, optional branches do not appear mandatory, completed history survives, and the next action still makes sense with reduced time today. Do not mark verification done based on a generated JSON artifact alone.

## Independent skill evaluation

When the user requests a blind comparison, use a fresh agent with no inherited conversation and a new application/data directory. Give only this skill, a realistic minimal user request and authorized original sources. Do not give the existing map, prior findings, expected counts, comparison rubric answers or derived captures. State allowed resource boundaries and preserve the full tool trace where available. Shared-host tool restrictions are instruction-level isolation unless an actual sandbox enforces them; do not describe them as stronger isolation.

Freeze and hash the candidate bundle, ledger, trace and skill version before showing the baseline to an evaluator. Compare facts and required coverage against sources; the old map is a comparison aid, not ground truth. Record omissions, additions, unjustified assumptions, blocked causes and contradictions in both maps. Revise the skill only for demonstrated failures. Retest affected behavior with a new independent pass or a separate representative task; do not overwrite the failed evidence or feed the expected answer to the new agent.

Publish only generic skill files, fictional test fixtures and a redacted evaluation summary. Keep real source content and transcripts private. A recommendation should state the tested scope and unresolved limitations; a small sample never demonstrates reliable completion of every occupation.
