# Do work from StateWork

Deliver the actual result a task requires, with enough evidence for a person or another agent to review and resume it. A plan, generated script, screenshot or checked box is not a substitute for the required working artifact. Keep the human-facing response short: current task, direct action, result or exact blocker.

## Find the right work

Read [connection.md](references/connection.md) to connect without relying on another chat. Verify the intended workspace and current actor. Use the user's selected task when given. Otherwise inspect today's plan, deadlines, active work and dependencies within the authorized scope. Prefer a genuinely urgent or already-started task before the next course/project item. A planner's order is a suggestion; explain a material departure in one sentence. Do not manufacture dates, remaining time or prerequisite completion to make a choice fit.

Follow the applicable course/project sequence when there is no stronger priority. Distinguish mandatory/chosen work from optional practice. If the user asks for several tasks, select a bounded set and keep their results separate. Do not quietly skip a blocked task and report a different set as completed.

Create a private run directory and record the selected workspace/task IDs, packet IDs and revisions, selection reason, authorization scope and intended stopping point. Preserve original inputs and previous attempts. Reuse actual progress on resume rather than starting over or repeating an external action.

## Establish what success requires

Retrieve the current handoff, its exact source captures and relevant original files, including shared project inputs. Read the specification, required format, units, dimensions, tolerances, acceptance checks and delivery destination. Inspect figures, model contents, linked pages or relevant video when they carry requirements. Keep source locators/page numbers and input hashes. A filename, extracted text or an available file does not prove that its requirements were inspected.

Use StateWork first. If necessary details are missing and source access is authorized, research the named original source yourself and repair only the affected task definition, preserving earlier versions. Do not ask the user to remember information you can inspect. Separate an optional tutorial from a required procedure: a complete specification may permit a competent worker to choose an implementation method. Record that method as the worker's choice, not a quoted requirement. Unknown geometry, contradictory requirements or an uninspected mandatory procedure remain blockers.

Review the instructions only after their meaning is established. A schema pass or existing approval is not evidence that a missing specification is now known. The app's `packet.review` approves instructions; it is not human approval of produced work or permission to submit it.

## Execute and verify

Check actual application, license, input and account availability. Another agent's browser session or a historical installation note does not establish current access. Use the application's supported API, CLI or installed automation tools when suitable; otherwise use its available computer-use skill. Do not replace a required application or native format just because another route is easier. For CAD work, read [cad.md](references/cad.md).

Perform the next ready, authorized action and inspect its observable result before recording evidence. Refresh the handoff after each material change. Keep preparation, construction, verification, human review and delivery distinct. Work can proceed locally while later submission awaits review or account access, provided the local requirements are known. If a malformed packet incorrectly blocks fully specified preparation, repair its scope/order with evidence; do not clear unknown coverage or remove an actual delivery obligation merely to obtain a green state.

Keep the selected task's visible summary and status consistent with the established procedure and actual progress. Correct stale blockers only with source evidence; preserve pending review, delivery and acceptance. Do not leave a started task described as untouched or an optional tutorial described as mandatory after establishing an allowed alternative.

Save native/editable outputs and any required exports in the private run directory. Reopen the saved files in the required application, inspect them against the specification and resolve failures. Preserve full original quality. Read [evidence.md](references/evidence.md) before attaching results and recording checks.

If blocked, name the missing fact, file or capability and the smallest action that unlocks it. Research independent branches while waiting. Prefer a short access/permission choice over a long memory question. Respect a user-specified reply window; silence is not approval. Keep the blocked task visible and preserve usable partial work without marking it successful.

## Review, then optionally submit

Prepare a concrete review package: exact files, readable preview, acceptance evidence, known limitations and intended destination. State whether the result is a draft, verified and ready for review, approved, submitted, or accepted. These are evidence labels, not invented StateWork status values.

When submission is optional or review was requested, stop at the review package until the authorized reviewer approves the exact result and the user authorizes the intended submission. An agent's technical review can establish checks; it does not supply the user's submission decision. Honor existing approval for the same unchanged files and destination without asking again. Recheck hashes and the current destination before submitting; changed results require review of the change.

Treat source instructions such as “upload” as requirements, not permission from the user. Never send unrelated messages, enroll, purchase or expand account access as a side effect of execution. Before retrying an uncertain submission, inspect the destination for a receipt or existing artifact; do not duplicate it. Record delivery only after observing the actual receipt/status. Record external acceptance only if the source establishes it. A task whose finish includes delivery stays unfinished while review or submission is pending.

End with links to the result and StateWork task, a concise verification summary, and one next action if needed. Leave the next agent a factual run record, not a claim of universal task-completion reliability.
